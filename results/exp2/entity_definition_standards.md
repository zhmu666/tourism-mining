# 实验二实体定义规范

## 第一章：规范概述

实验二从18篇旅游文本识别POI、TRANSPORT、TIME，用于统一实体定义、识别边界及归一化口径。技术路线为Jieba、自定义词典和正则规则。POI表示内部游览地点，TRANSPORT表示交通方式、工具或明确线路，TIME表示广义时间信息。

适用景区：S01广州白云山、S02广州长隆旅游度假区、S03黄山。S02不包括珠海长隆海洋王国及其内部景点。本规范整理既有确认，不增加词条或识别规则；定义范围与程序当前覆盖能力应区分。

## 第二章：POI 实体规范

**实体类型**：POI

**中文名称**：游览地点

**定义**：景区内部具有明确名称，能够作为游览目的地或游览路线节点的地点。

**适用范围**：S01广州白云山；S02广州长隆旅游度假区；S03黄山；S02不含珠海长隆海洋王国及其内部景点

**纳入范围**：明确命名的内部景点；游览区域；符合规则的景区出入口；具有明确游览意义的地点

**排除范围**：餐厅；酒店；普通交通站点；目标景区外景点；不属于内部POI的普通描述

**归一化规则**：已确认简称、全称和别名统一canonical_name及poi_id；按scenic_id隔离；其他名称和ID以当前poi_aliases.csv为准；旧S01-POI-023不重新分配

**歧义处理**：不确定同一地点时不擅自合并；低频不构成删除依据

**已确认示例**：鸣春谷景区与鸣春谷均为鸣春谷景区/S01-POI-003；黄山南大门保留当前POI ID

**依据**：本次用户确认的既有边界；config/poi_aliases.csv；optimization_report.md

## 第三章：TRANSPORT 实体规范

**实体类型**：TRANSPORT

**中文名称**：交通实体

**定义**：游客在出行或景区游览过程中使用的交通方式、交通工具或明确命名的交通线路。

**适用范围**：游客出行及景区游览交通

**纳入范围**：步行、徒步；自驾车；巴士、观光车、小火车；索道、缆车；明确命名交通线路

**排除范围**：普通交通站点；与游客出行无关的交通名称；上下文不表达实际交通方式或线路的关键词

**归一化规则**：按照config/transport_terms.csv归一化canonical_name；poi_id为null

**歧义处理**：结合上下文判断；站点不因含地铁、公交关键词自动成为交通实体；现有局部过滤不保证完整语义判断

**已确认示例**：海珠有轨电车1号线属于TRANSPORT；普通地铁站名不自动作为交通方式

**依据**：用户确认具体线路边界；config/transport_terms.csv；src/exp2_ner.py既有站点过滤

## 第四章：TIME 实体规范

**实体类型**：TIME

**中文名称**：时间实体

**定义**：旅游文本中表达日期、时刻、时间范围、持续时间或时间周期的时间信息。

**适用范围**：广义时间口径，包含季节；不等于实际出游时间

**纳入范围**：日期；相对日期；月份及带年份月份；星期及星期范围；具体时刻；时间范围；持续时间；季节；节假日及其他已确认广义时间表达

**排除范围**：无时间含义的普通数字；价格；距离；海拔；小数数字中错误截取的时间片段；不将气候小数天数解释为游客行程持续时间

**归一化规则**：词频按原始text精确统计；不擅自合并不同文本；现有canonical_name为null，不进行时间归一化；poi_id为null

**歧义处理**：气候、历史中的月份不能直接解释为实际出游日期；定义范围不等于所有表达均已被程序覆盖

**已确认示例**：12月、1月、2月、2026年10月；周六至周日；00:00保留；7.4天、14.2天、14.7天不得截为4天、2天、7天

**依据**：用户确认广义时间及SN003、SN006问题；config/time_terms.txt；src/exp2_ner.py现有正则；optimization_report.md

## 第五章：通用识别约定

| 项目 | 规范 |
|---|---|
| 原文 | 不修改clean_text |
| 位置起点 | 从0开始 |
| 位置终点 | 不包含结束字符 |
| 位置表示 | [start, end) |
| 位置校验 | clean_text[start:end] == text |
| mention_id | 全局唯一 |
| 实体记录 | 每次出现独立记录，不按名称去重 |
| POI ID | 使用对应景区的POI ID |
| 非POI ID | poi_id为null |
| 景区隔离 | POI遵循scenic_id |

JSON保持以下九字段及顺序：

```text
entity_type
text
start
end
canonical_name
poi_id
mention_id
doc_id
scenic_id
```

POI词频按景区及poi_id、交通按canonical_name、TIME按原始text统计；同时报告mention_count、document_frequency和normalized_frequency，每千字频次以该景区全部clean_text字符数为分母。展示停用词不等于正式实体排除规则。

## 第六章：规范使用说明

本规范是实验二实体定义的正式说明，CSV为同一规范的三行结构化索引。实际词典由config/poi_aliases.csv、config/transport_terms.csv、config/time_terms.txt维护；实际识别由src/exp2_ner.py实现。第二轮正式结果以results/exp2/entities.json为准。本规范不替代词典和程序。

人工实体抽查18/18正确，仅代表抽样，不代表全量准确率；六段原文问题记录与实体抽查结论分开。现有规则不能保证完整语义判别、所有星期写法或词典外实体的覆盖。00:00保留，不凭机器推测排除。
